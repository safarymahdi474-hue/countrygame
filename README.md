# Country Game Bot — فاز ۱: اسکلت پروژه

## چی تو این فاز ساخته شد
- ساختار پوشه‌ای پروژه (`bot/handlers`, `bot/models`, `bot/services`, `bot/keyboards`, `bot/database`, `bot/config`)
- تنظیمات پروژه (`bot/config/settings.py`) — همه مقادیر حساس از env می‌خونه
- اتصال دیتابیس async با PostgreSQL + SQLAlchemy (`bot/database/engine.py`)
- سه مدل هسته:
  - `User` — کاربر تلگرامی
  - `World` — دنیا/فصل بازی (چند world مستقل مثل بازی منبعِ الهام، ولی منطق فصل‌بندی‌ش بعداً خودمون طراحی می‌کنیم)
  - `Country` — کشور بازیکن، با محدودیت «یک اکانت = یک کشور در هر world»

## چرا این تصمیم‌ها
- **Numeric به‌جای float** برای پول و امتیاز — تا خطای گرد کردن اعشار تو محاسبات مالی رخ نده (مشکلی که خیلی از این‌جور بازی‌ها دارن)
- **امتیاز هر دسته cache شده روی خود Country** — برای رتبه‌بندی سریع بدون join سنگین؛ به‌روزرسانیش وظیفه‌ی سرویس‌های فاز بعده
- **تیرهای کشور (standard/advanced/elite)** — اسم و مقدار مزایا عمداً متفاوت طراحی شده؛ فرمول دقیقش رو تو فاز اقتصاد با هم می‌بندیم

## فاز بعدی (اقتصاد و منابع)
قبل از شروع فاز ۲ باید این‌ها رو با هم تصمیم بگیریم:
1. چند نوع منبع خام داریم؟ (فولاد/نفت/اورانیوم مثل قبل، یا ست جدید؟)
2. فرمول رشد منابع بر اساس سطح ساختمان چطور باشه؟ (خطی، نمایی، یا پلکانی؟)
3. آیا سیستم فصل (تابستان/پاییز و ...) رو نگه می‌داریم یا حذفش می‌کنیم؟

## اجرای محلی
```bash
pip install -r requirements.txt
cp .env.example .env   # و پرش کن
```

### مایگریشن دیتابیس (Alembic)
روی دیتابیس واقعی (Postgres)، به‌جای `create_all` از Alembic استفاده کن:
```bash
alembic upgrade head          # اعمال آخرین مایگریشن‌ها
alembic revision --autogenerate -m "توضیح تغییر"   # بعد از تغییر مدل‌ها
```
`migrations/env.py` خودش از `DATABASE_URL` محیطی یا `alembic.ini` می‌خونه و
تمام مدل‌های `bot.models` رو برای autogenerate می‌شناسه.

### اجرای ربات
```bash
python -m bot.main
```
(فعلاً `main.py` هم به‌صورت fallback یه `create_all` می‌زنه تا برای تست سریع
لازم نباشه حتماً Alembic رو دستی اجرا کنی؛ رو دیتابیس تولید، بهتره این خط
حذف بشه و فقط از مایگریشن‌ها استفاده بشه.)

### تست‌ها
```bash
pytest
```
همه‌ی تست‌ها با SQLite درون‌حافظه‌ای اجرا می‌شن (نیازی به دیتابیس واقعی نیست).

### دیپلوی روی Railway
`Dockerfile` و `railway.json` آماده‌ان — روی Railway کافیه پروژه رو وصل کنی،
`BOT_TOKEN` و `DATABASE_URL` (پلاگین Postgres خود Railway) رو ست کنی؛
`CMD` داخل Dockerfile اول مایگریشن رو می‌زنه، بعد ربات رو بالا میاره.
